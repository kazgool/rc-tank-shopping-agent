# Output Directory

This directory contains all outputs generated by the RC Tank Shopping Agent.

## Directory Structure

```
output/
├── screenshots/    # Browser screenshots captured during operation
├── reports/        # Generated shopping reports (JSON and TXT)
└── logs/          # Application logs
```

## Screenshots (`screenshots/`)

The agent automatically captures screenshots at key moments:

- **Search Results**: `[Platform]_search_[query]_[timestamp].png`
- **Product Pages**: `[Platform]_product_[part_name]_[timestamp].png`
- **Cart/Wishlist**: `[Platform]_added_to_cart_[timestamp].png`
- **Errors**: `[Platform]_error_[timestamp].png`

### Naming Convention
- Screenshots are numbered sequentially: `001_`, `002_`, etc.
- Include platform name, action type, and timestamp
- Full page screenshots for complete context

### Usage
- Review screenshots to verify agent behavior
- Debug issues by seeing what the agent sees
- Verify product matches visually

## Reports (`reports/`)

Generated after each shopping run:

### JSON Format
`shopping_report_YYYYMMDD_HHMMSS.json`

Structured data including:
- Complete search results
- Product specifications
- AI analysis and reasoning
- Price comparisons
- Confidence scores

Example structure:
```json
{
  "timestamp": "2026-01-06T10:30:00",
  "total_parts": 20,
  "found": 15,
  "not_found": 5,
  "results": [...]
}
```

### Text Format
`shopping_report_YYYYMMDD_HHMMSS.txt`

Human-readable report with:
- Summary statistics
- Part-by-part analysis
- Best matches highlighted
- Price comparisons
- AI recommendations

### Usage
- Review after each run
- Compare prices across platforms
- Verify AI matching decisions
- Track which parts were found

## Logs (`logs/`)

### Main Log File
`shopping_agent.log`

Detailed application logs including:
- All operations performed
- Success and error messages
- API calls and responses
- Timing information
- Stack traces for errors

### Log Levels
- **DEBUG**: Detailed diagnostic information
- **INFO**: General informational messages
- **WARNING**: Warning messages
- **ERROR**: Error messages
- **CRITICAL**: Critical issues

### Log Rotation
- Automatically rotates at 10 MB
- Keeps last 10 days of logs
- Compressed older logs

### Usage
- Troubleshoot issues
- Monitor agent performance
- Track API usage
- Debug platform-specific problems

## Cleaning Up

These directories can grow large over time. To clean up:

```bash
# Remove old screenshots (older than 7 days)
find output/screenshots -name "*.png" -mtime +7 -delete

# Remove old reports (older than 30 days)
find output/reports -name "*.json" -mtime +30 -delete
find output/reports -name "*.txt" -mtime +30 -delete

# Compress old logs
find output/logs -name "*.log" -mtime +7 -exec gzip {} \;
```

## Git Ignore

By default, all files in these directories are ignored by Git (except `.gitkeep`):
- Screenshots can be large
- Reports may contain personal data
- Logs can accumulate quickly

If you want to commit specific outputs, use:
```bash
git add -f output/reports/specific_report.json
```

## Best Practices

1. **Regular Review**: Check outputs after each run to verify agent behavior
2. **Archive Important Reports**: Save successful reports to a separate location
3. **Monitor Disk Space**: These directories can grow large with many runs
4. **Clean Periodically**: Remove old screenshots and reports you don't need
5. **Check Logs on Errors**: Always review logs when something goes wrong

## File Sizes

Typical file sizes:
- Screenshot: 50-200 KB each
- JSON Report: 5-50 KB each
- Text Report: 2-10 KB each
- Log file: Grows continuously, rotates at 10 MB

## Privacy Note

⚠️ **Important**: These directories may contain:
- Product names you searched for
- Prices and specifications
- Browsing patterns
- Your search history

**Do not share these files publicly** if they contain sensitive information.
